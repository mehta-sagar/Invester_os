# Brief S0-T4: Collector base class
- Stage 0 · Branch: task/S0-T4 · Algorithm §4 "What every collector does"
## Goal
`investos.collect.base.Collector`: subclasses implement `keys(run_range)`, `url(key)`, `check_body(key, resp) -> BodyVerdict`. Base handles: per-host rate limit (default 0.35 s), 3 retries with backoff then stop-and-log; no header spoofing; body check before storing (HTTP 200 is not proof); four outcomes per key, kept separate: `fetched`, `fetched_empty`, `missing_holiday`, `unreadable`; plus `skipped` when the manifest already holds the key (re-run fetches nothing); paged source returning exactly its page limit → `incomplete`. Writes via manifest writer only; never parses. Writes a run sidecar JSON: status, expected vs received count, gap list, output hashes; a run with gaps never replaces a complete sidecar for the same range. Zip-slip and zip-bomb guards for archives.
HTTP is injected (transport interface) so tests run offline with a fake server.
## Done means
- [ ] exit-gate demos 1–3 pass as tests: fetches one file; broken body rejected (`unreadable`, nothing stored); re-run → all `skipped`, zero HTTP calls
- [ ] planted failures: BSE-style 200 error page, page-limit hit, zip-slip path, 4th retry not attempted, gap sidecar not overwriting complete one
