# Spec collect_rss   (from brief S1-T6, task S1-SPEC3, 27 Nov 2026)

The first real collector adapter: a poller for RSS feeds (NSE's 22 corporate feeds, decision 0002 point 2, plus a few official and press news feeds for the Daily Market Journal). Always `honest` access mode (decisions 0002/0002a): no cookies, no Referer, no browser. Modules: `src/investos/acquire/rss.py` (adapter, feed table loader, poll cycle, state, gap ledger), `src/investos/acquire/registry.py` (adapter registry, R21), `src/investos/parse/rss_items.py` (item extractor, the only parser, R14-R16), `src/investos/check/rss_check.py` (check `rss`), CLI `investos collect rss [--once]` in `src/investos/cli.py`, tables `config/rss_feeds.csv`, example scheduler `ops/launchd/com.investos.rss.plist.example`. A small amendment of `src/investos/acquire/base.py` (R7). Python 3.11+, stdlib only. All HTTP goes through the base `Transport`; time, sleep and notifier are injected so tests run instantly. Rule numbers here are this spec's own (R1...), tests A1...; "base R17" means rule R17 of `specs/collect_base.md`.

Evidence base: `specs/collect_base.md` (outcomes, R17-R33 access, R34-R41 date check), `specs/core_manifest.md` (OQ3 resolution: 15-minute poll, an unchanged body writes no row), `specs/trading_calendar.md` (`day_status`, `DayStatus`), `specs/ops_roots_routine.md` (launchd example, add-list), `specs/check_runner.md` (checks and plants), `docs/decisions/0002*.md`. Facts marked (research) come from the Plan project's research notes (NSE RSS directory, robots.txt, T14), not re-verified here.

## Inputs (schema)

### `config/rss_feeds.csv`: the feed table (R3)
Header `feed_id,url,kind,publisher,enabled,stale_after_min,stale_scope,status,note`. One row per feed.
- `feed_id`: `^[a-z0-9][a-z0-9_]{0,47}$`, unique; part of every logical key, so never renamed after the first poll (a rename is a new feed).
- `url`: `https` URL, host lowercase, no userinfo, no fragment, at most 300 characters. It must be the FINAL url (R4).
- `kind`: `corporate` (NSE filings feeds) or `news`. `publisher`: non-empty text. `enabled`: `yes`/`no`. `note`: free text, may be empty.
- `stale_after_min`: int >= 15, the content window (R13). `stale_scope`: `trading_hours` (judged only on NSE trading days, R13) or `always`.
- `status`: `confirmed` (a Mac probe fetched it and the body parsed) or `to_confirm`.

## Outputs (schema)

- Raw feed bodies: only through `ManifestStore.store` (base R11), source `rss`, `source_version = "rss-v1"`, `logical_key = "<feed_id>/<slot>"`, byte-exact, one row per CHANGED body.
- Run sidecars: base R13, one per feed per IST day at `<manifests zone>/rss.runs/<feed_id>/<IST date>_<IST date>.json` (the base overwrites it each poll; R14 of the base writes an `attempt-` file only when a failing poll follows a complete one).
- Feed state, one JSON file per feed, untracked machine state `<ledger zone>/.state/rss/<feed_id>.json` (R11).
- Gap ledger, append-only tracked JSONL `<ledger zone>/rss/gaps.jsonl` (R12).
- Item rows: the in-memory output of `extract_items` (R14). Loading them into the canonical store and the Journal is a later task.
- Report of the check: `reports/checks/<run_id>.json` as for every check.

## Rules (numbered, each gets at least one test and one planted failure)

R1. Adapter identity. `RssFeedCollector`: `source = "rss"`, `source_version = "rss-v1"`, `access_mode = HONEST`, `date_keyed = False`, `date_check_waiver = None`, `page_limit = None`, `archive = False`, `extra_headers = {}`, `keys()` yields the single key it was built with. No `[collect.access.rss]` table may exist: base R17 already refuses a config entry that disagrees with an honest class, and a test pins it. The adapter only ever requests the URL of its `FeedRow`, over `https`, with the base's honest identity (`InvestOS/<version> (personal research; <contact>)`, base R19/R20). The CLI refuses to start (exit 1, message `collect.contact is not configured`, before any file under `data/` is touched and before a transport is built) while `[collect] contact` is empty or the `.invalid` placeholder, as in base A58.

R2. Logical key. A feed has no trade date, so the poll key is `<feed_id>/<slot>`, `slot = slot_of(now)` = the IST wall time floored to a 15-minute boundary, formatted `YYYYMMDDTHHMM` (for example `online_announcements/20261127T1445`). The key is an identity for "this feed polled in this slot", not a date. Consequences: `date_keyed = False`, so base R34-R41 (in-file date check, `rejected`) do not apply and the sidecar says `date_check = "not_date_keyed"`. A feed is a rolling window of the latest items; there is no requested date to compare an in-file date with, and a stale feed is caught by R13 instead, which is the equivalent test (the newest item's date against the clock). The class must not set `date_keyed = True` (a test asserts it). The manifest check treats keys as opaque text, so the `/` and `T` are fine.

R3. Feed table validation. `load_feeds` raises `FeedTableError` naming file, row and column for: a wrong header or extra/missing column; a bad or duplicate `feed_id`; a `url` that is not `https`, has userinfo, a fragment, uppercase host, spaces, or exceeds 300 characters; `kind`, `enabled`, `stale_scope` or `status` outside their sets; `stale_after_min` not an integer >= 15 (a bool or float-looking text fails); an empty `publisher`; a duplicate `url`; a file that is not UTF-8 or has a NUL. Disabled rows are validated too. The file is read-only for the code. Zero enabled rows is legal (the cycle does nothing, exit 0, a WARNING is logged).

R3a. Shipped table (Sagar, 27 Nov 2026, after the probe). `config/rss_feeds.csv` ships 26 rows, all `enabled=yes`, all `status=confirmed` (every one fetched 200 and parsed in the probe): the 23 NSE corporate feeds plus NSE `Circulars` at `https://nsearchives.nseindia.com/content/RSS/<name>.xml` (names exactly as in the probe report), `rbi_press` and `sebi_press`. `feed_id` = the file name lower-cased (`online_announcements`, `annual_reports`, `board_meetings`, `brsr`, `corporate_action`, `corporate_governance`, `daily_buyback`, `financial_results`, `integrated_filing_financials`, `insider_trading` (keeps the R3 id), `investor_complaints`, `offer_documents`, `related_party_trans`, `sast_regulation29`, `sast_regulation31`, `sast_reasonforencumbrance`, `secretarial_compliance`, `share_transfers`, `shareholding_pattern`, `statement_of_deviation`, `unitholding_patterns`, `voting_results`, `circulars`), publisher `NSE`, kind `corporate` (Circulars too). Windows: `online_announcements` 90 `trading_hours`, `insider_trading` 360 `trading_hours`, `circulars` 2880 `trading_hours`, `rbi_press`/`sebi_press` 5760 `always`; every other NSE feed `525600` `always` (one year: these files can go months without an item, e.g. Share_Transfers last item May 2026, so a content alarm would be noise; `poll_missed` still guards them). The R3 4-row table is replaced by this one; the per-row rules of R3 are unchanged.

R4. URL discipline. The base never follows redirects and the adapter does not either: a 3xx response is `unreadable` with reason `redirect to <location header, first 200 chars>` and nothing is stored (the `.com` to `.in` 302 of research is handled by correcting the table, never by following). The table holds the final URL, so a probe that sees a 302 changes the row. No retry on 3xx, no header change (base R2/R19).

R5. Body check. `check_body` returns: `UNREADABLE` for non-XML, an HTML page, a body that fails `parse_feed`, a root other than RSS 2.0 (`rss`, with a `channel`; Atom or RDF give reason `unsupported feed format <root>`), or a body over 8 MiB; `FETCHED_EMPTY` for a valid RSS body with zero items (a quiet window is legal, for example InsiderTrading overnight); `FETCHED` for one with at least one item, `record_count` = item count. HTTP 200 is never proof (base R6). The adapter extracts nothing else from the body (only `parse_feed`'s validity and count).

R6. Parser safety. `parse_feed` uses `xml.etree.ElementTree` only (stdlib). Before parsing it rejects (raises `FeedParseError`) any body whose first 4 KiB or any later part contains `<!DOCTYPE` or `<!ENTITY` (case-insensitive), or a NUL byte, or is over 8 MiB. No external resolution, no network, no `lxml`, no `defusedxml` dependency. The base stays parser-free: `base.py` still imports no XML parser (base A25/A70 re-run); `rss.py` may import `parse_feed` but not an XML module itself.

R7. Base amendment: unchanged body. `Collector` gains a hook `def unchanged_body(self, key: str, sha256: str, body: bytes) -> str | None` (R8a: the body is passed so an adapter can judge a content digest; the base never interprets it) (default `None`). After a `FETCHED`/`FETCHED_EMPTY` verdict has passed every existing step (page limit, archive, date check) and before anything is stored, the base computes the body's sha256 and calls the hook; a non-empty string result makes the outcome `skipped` with that string as reason, and nothing is stored (no raw file, no manifest line). Such a key counts in `skipped`, counts toward `received` (so the run can be `complete`), is not a gap, has no row in the sidecar `outputs`, logs INFO `skipped` with the reason, and its HTTP call stays counted in `http_calls`. Base R9 (zero HTTP, zero sleeps for a manifest hit) is unchanged and still comes first. A hook that raises, or returns a non-str non-None, is ignored (the body is stored) with WARNING `unchanged_hook_error`: the rule fails toward keeping evidence. The default `None` leaves every existing collector and test unchanged.

R8. Dedup rule. `RssFeedCollector.unchanged_body` returns `"unchanged_body"` iff `last_stored_sha` (read by the cycle from the feed state, R11) is not `None` and equals `sha256`; otherwise `None`. The comparison is on the raw bytes' sha, nothing smarter (decision of 21 Nov, core_manifest resolved 3). A missing, corrupt or older state file means "no last sha": the body is stored once more (harmless extra row), never skipped on a guess. An all-identical poll therefore costs one HTTP call and no row; a changed body costs one row.

R8a. Dedup on a content digest (Sagar, 27 Nov 2026, answer to the probe question; supersedes the "raw sha, nothing smarter" sentence of R8). The live probe (reports/S1-T6/PROBE_2026-11-27.md) found that 13 NSE feeds rewrite only `<lastBuildDate>` about every 10 minutes with no item change, which under R8 would store a noise row every poll (~4 GB/year). So the dedup compares a content digest, not the raw sha: `content_digest(body: bytes) -> str` in `acquire/rss.py` = sha256 hex of the body with every `<lastBuildDate>...</lastBuildDate>` element (byte regex `rb"<lastBuildDate>[^<]{0,200}</lastBuildDate>"`, exact case, no XML parsing) replaced by the empty byte string. `unchanged_body` returns `"unchanged_body"` iff the state's `last_content_digest` is not `None` and equals `content_digest(body)`; otherwise `None`. Storage is unchanged: when a body IS stored it is stored byte-exact with its raw sha (R5, base R11); `last_stored_sha` keeps the raw sha and the state gains `last_content_digest` (the digest of that same stored body), set only when a body is stored, `null` before. The state `schema` stays 1 (never shipped). Everything else in R8 holds: a missing or corrupt state means no digest, so the body is stored, never skipped on a guess; A, B, A stores the third body again (compared only with the last stored digest). A body whose ONLY difference is inside `<lastBuildDate>` is skipped; any other byte difference (an item, a `<pubDate>`, whitespace outside that element) stores a new row.

R9. Poll schedule. Scheduled slots: every 15-minute slot from 07:00 to 23:45 IST, plus three overnight slots `01:00`, `03:00`, `05:00` IST; no other slot between 00:00 and 06:45 (Sagar's open question 1). `is_poll_slot(slot)` encodes exactly that. The scheduler fires every 15 minutes (R19); when the current slot is not scheduled, `poll_cycle` returns `skipped_slot = True`, makes zero HTTP calls and writes nothing, unless `force` (`--force` flag for a manual run). Slots are computed from the injected clock converted with `ZoneInfo("Asia/Kolkata")`, never from the host's local zone.

R10. Poll cycle. For one slot, `poll_cycle`: (1) validates the table (`FeedTableError` aborts with exit 2, nothing fetched); (2) detects gaps (R12); (3) for each enabled feed in table order, with NSE hosts first by table order only (no sorting), skips the feed with zero HTTP if its state says `last_ok_slot == slot` (this slot already succeeded: two scheduler fires in one slot do not poll twice); (4) otherwise builds one `RssFeedCollector` for `(feed, slot)` and calls `run(RunRange(today_ist, today_ist))` with the per-feed `sidecar_dir`. One run per feed: a retry-exhausted or blocked key aborts only that feed's run (base R8), and a host block (base R24) makes the other feeds on that host `not_attempted` without HTTP while feeds on other hosts proceed. Feeds are fetched sequentially, one request at a time; (5) updates state (R11) and records failures (R12); (6) evaluates freshness (R13) and notifies. A cycle stops starting new feeds once `10 * 60` seconds (monotonic) have passed since it started: the remaining feeds are recorded as failed slots (`reason = "cycle budget"`), so a slow host cannot overlap the next slot. Unknown exceptions from one feed are caught, logged ERROR, recorded as a failed slot, and the cycle continues; `KeyboardInterrupt` propagates.

R11. Feed state file. `<ledger zone>/.state/rss/<feed_id>.json`, canonical JSON, temp file plus fsync plus `os.replace`: `{"schema":1,"feed_id","last_attempt_at","last_ok_slot","last_ok_at","last_stored_sha","last_content_digest","last_change_at","newest_pub_ist","consecutive_failures","alerted":{"<kind>":"<IST date>"}}`; timestamps UTC `...Z` (6 digits), `newest_pub_ist` an ISO string with `+05:30` or `null`, `last_stored_sha` the sha of the newest body stored for the feed. A poll is "ok" when the key's outcome is `fetched`, `fetched_empty` or `skipped` (either cause); on ok: `last_ok_slot`, `last_ok_at`, `consecutive_failures = 0`; `last_stored_sha`, `last_change_at` and `newest_pub_ist` (maximum `pub_ist` among the body's items, from `parse_feed`) change only when a body was stored. On any other outcome `consecutive_failures += 1` and only `last_attempt_at` moves. The file is machine state: untracked (`data/ledger/.state/` is already git-ignored, base R25), never read as proof of what was fetched (the manifest is), never needed for correctness: a missing, invalid or schema-mismatched file is treated as absent (WARNING `state_unreadable`), which can only cause one extra stored row (R8) and a missing freshness verdict (WARNING in the check), never a skipped body or a false "fresh". Per-feed files are written only by the cycle (one process at a time per feed, guarded by an `flock` on `<feed_id>.lock`; a second cycle that cannot take it within 5 s exits 0 with reason `cycle already running`).

R12. Poll-miss detection and the gap ledger. A "miss" is a scheduled slot (R9) strictly between a feed's `last_ok_slot` and the current slot with no ok poll (the Mac was off or asleep, the process died, a cycle lacked budget); a "failure" is the current slot's key ending as `unreadable`, `incomplete` or `not_attempted`. Both are written to `<ledger zone>/rss/gaps.jsonl`, append-only, one canonical-JSON line per feed per contiguous run of slots: `{"schema":1,"feed_id","kind":"missed"|"failed","from_slot","to_slot","slots":<int>,"reason","detected_at":"<UTC>","run_id"}`. Same writer discipline as the access files (base R25: exclusive `flock`, one write, fsync, fsync the directory on creation, refuse a torn tail; strict reader). Nothing is written when `last_ok_slot` is absent (first run: nothing known to be missed) or for slots before the feed's first ok poll. A gap writer that fails (unwritable, torn tail) makes the cycle exit 1 with ERROR `gap_write_failed` after the other feeds were polled. Events are never edited or deleted; the later real-browser backfill runner (separate spec) reads this file to know what to gap-fill and appends its own `filled` events. Missing data is a recorded gap, never silently skipped (the feeds are rolling windows with no backfill, research). The gaps file is added to the roots routine's add-list (`specs/ops_roots_routine.md`, the same way as the access files).

R13. Freshness rule and alarms, per enabled feed. Evaluated at the end of every cycle and by the check (R20), from the state file and the injected clock. Two alarm kinds: (a) `poll_missed`: the latest scheduled slot that is at least 10 minutes old has no ok poll (`last_ok_slot < that slot`), or `consecutive_failures >= 3`; (b) `content_stale`: the age of the feed's content exceeds `stale_after_min`. Content age = now minus `newest_pub_ist`; if that is `null` (no item ever, or all unparseable) then now minus `last_change_at`; if both are null the verdict is `unknown` (a WARNING, never an alarm: nothing was ever polled). With `stale_scope = trading_hours` the rule is evaluated only when the IST date has `TradingCalendar.day_status` in `TRADING` or `PROVISIONAL` (NSE, CM) and the IST time is between 09:30 and 16:00, and the age is measured from the later of `newest_pub_ist` and 09:15 IST of that day (so Monday morning is not stale because of Friday's last item); with `always` the age is plain. When the calendar tables are not loaded for the year (`UNKNOWN`) the feed is judged as `always` and a WARNING says so. An alarm calls `notifier.notify("Invest OS: feed stale", "<feed_id> <kind>")` (text names the feed and kind only, no URL, no header values) at most once per feed per kind per IST day (the state `alerted` map), and logs ERROR `feed_alarm`. A feed that recovers clears nothing in the state; the next IST day can alarm again.

R14. Items, step two: the extractor. `extract_items(rows)` turns stored raw bodies into item rows. `rows` are `(ManifestEntry, body bytes)` pairs of one source in manifest order; the function does no I/O and reads no clock. For each row it takes `feed_id` from `logical_key.split("/")[0]`, calls `parse_feed` (a body that raises `FeedParseError` is skipped and logged WARNING `item_parse_failed` with the sha; it never stops the stream), and yields an `ItemRow` for every item whose `(feed_id, item_id)` has not been yielded before, so each item appears once, at its first sighting. `first_seen_at` = the manifest `fetched_at` of the earliest stored row containing the item: the moment WE saw it, never `pub_ist`. `first_seen_sha256`, `first_seen_key` identify that row. `pub_after_seen = pub_ist is not None and pub_ist > first_seen_at + 5 minutes` flags publisher clocks ahead of ours. Point in time rule: the field a backtest or the Journal may use as "known at" is `first_seen_at`; `pub_ist` is the publisher's claim and is data, not knowledge time. First sighting is only as precise as our polling (up to one slot, and later after a recorded gap, R12): `first_seen_at` is an upper bound on when the item became public, never a lower one, which is the safe direction. Because only changed bodies are stored (R8), the first stored row containing an item is its first sighting; unchanged polls add nothing and lose nothing.

R15. pubDate is IST text. `pub_ist` is an aware `datetime` in `Asia/Kolkata`. A `pubDate`/`dc:date` text with no zone (the NSE feeds, trap T14) is read as IST wall time, never as UTC. A text with an explicit zone (`+0530`, `+0000`, `GMT`, `UT`, `Z`) is honoured and converted to IST. Accepted spellings: RFC 822 with or without weekday and with or without seconds (`Fri, 27 Nov 2026 14:05:00 +0530`, `27 Nov 2026 14:05`, `27-Nov-2026 14:05:00`), and ISO 8601 (`2026-11-27T14:05:00`, with or without offset). A date with no time (as in older NSE sources before about 2012) is `date_only`: `pub_ist` = 23:59:59 IST of that date (end of day, the conservative reading for a point in time use). Nothing parseable: `pub_ist = None`, `pub_status = "unparseable"` (text kept in `pub_raw`), the item is still emitted; no element: `missing`. Never `datetime.now()` as a fallback, never a drop.

R15a. Probe addendum (Orchestrator, 27 Nov 2026, reports/S1-T6/PROBE_2026-11-27.md). The live feeds use these spellings; each must parse per R15: month names in any letter case (`11-SEP-2026 17:49:09`); ISO 8601 with a space instead of `T` (`2026-11-27 18:08:28`); a date-only text with a comma after the day and a zone (`27 Nov, 2026 +0530`, `date_only`, 23:59:59 IST of that date); `27-Nov-2026 22:39` (no seconds); `27-Nov-2026` (`date_only`). Items with no `pubDate` exist on live NSE feeds (`missing`). Nothing else in R15 changes.

R16. Item identity and fields. `item_id` = the `guid` text (stripped) if non-empty, else the `link`, else `"h:" + sha256(title + "\n" + (pub_raw or ""))`. Before use as id, a link whose host is `nsearchives.nseindia.in` or `www.nseindia.in` is rewritten to the matching `.com` host (research: the `.com` to `.in` move would otherwise make every item new); the stored `link` field keeps the original text. `title` and `summary` are stripped text (`summary` = `description` content with markup tags removed, whitespace collapsed, at most 2000 characters; title at most 1000); control characters are removed. Two items with the same id in one body keep the first. Item order inside a body does not matter.

R17. Rate and volume. The base limiter applies unchanged (base R27/R28): `nsearchives.nseindia.com` 1.0 s in the example config, other hosts the default 0.35 s; this spec adds `"www.rbi.org.in" = 1.0` and `"www.sebi.gov.in" = 1.0` to `config/investos.example.toml` `[rate_limits.hosts]` (the file must still load). 22 NSE feeds plus N news feeds per 15 minutes is under 40 requests per slot, about 3,000 per day at most (40 feeds x 76 slots), against a limiter that would allow thousands per hour; no `daily_cap` is required for an honest adapter and none is set. A block (401/403/429/451 or challenge) is handled by base R24-R26 (host day-block, halt after 3 blocked days in 7) and the poller never retries or changes identity.

R18. CLI. `investos collect rss [--once] [--force] [--dry-run]`. `--once` is the only mode: one `poll_cycle` for the current slot, then exit (the scheduler provides the repetition; a resident loop is out of scope). `--force` polls even when the slot is not scheduled. `--dry-run` validates the feed table and prints the due feeds and slot, with no HTTP, no write. Without `--once` the command prints usage and exits 2. Exit codes: `0` cycle ran (feed failures are recorded gaps, not exit codes) or nothing was due; `1` start refused (empty contact, config error, access state unreadable at start); `2` usage error or feed table invalid. The command wires `UrllibTransport`, `ManifestStore.from_config`, `OsascriptNotifier` (macOS) and the clock; `build_collector`-style construction shares the contact refusal of base A58.

R19. Scheduling example. `ops/launchd/com.investos.rss.plist.example` is a valid property list (`plistlib` loads it) in the style of `com.investos.roots.plist.example`: `Label` `com.investos.rss`, `ProgramArguments` `investos collect rss --once`, `StartInterval` 900 (seconds) and `RunAtLoad` true, log paths under `data/ledger/.state/`, and a comment that launchd uses the Mac's local zone (slots are computed in IST from the clock, so the zone does not matter for slots) and that a sleeping Mac skips slots, which R12 then records as `missed`. Installing it is a human step. The roots routine (23:30) and the poller are independent processes; the poller never commits or pushes.

## Edge cases
- A feed whose XML carries a volatile element (a build timestamp) changes its sha every poll: every poll stores a row. Not suppressed (raw bytes stay exact, R8); the Mac probe measures this per feed and reports the row growth before the feed is enabled.
- Two scheduler fires inside one slot: the second finds `last_ok_slot == slot` and does nothing (R10); if the first failed, the second retries the feed (state not ok).
- Mac wakes at 08:20 after sleeping since 02:00 (last ok slot 01:00): slot 08:15 polls, and the scheduled slots 03:00, 05:00, 07:00 to 08:00 are recorded as one `missed` event per feed (contiguity is counted among scheduled slots only).
- Body returns 200 with an empty feed (zero items): `fetched_empty`, stored once; an identical empty body next poll is skipped.
- Feed body changes from items to an HTML block page: `unreadable` (and, if the host's configured challenge signatures match, a block per base R24). Nothing is stored.
- Daylight saving: IST has none; `slot_of` uses `ZoneInfo`. A clock that moves backwards produces a slot earlier than `last_ok_slot`; the cycle then polls (`last_ok_slot != slot`) and records no gap.
- A feed removed from the table keeps its manifest rows and state file; the check reports its keys as unknown only if the feed id is absent from the table (R20), so removal is a conscious `enabled = no`, not a delete.
- `pubDate` in the future by hours (publisher clock): item emitted, `pub_after_seen = True`; the content-age rule uses `min(newest_pub_ist, now)` so a future date cannot hide a stale feed.
- Transient 5xx: base retries (up to 4 attempts, 1 + 2 + 4 s backoff), inside the 10-minute budget.

1. Overnight polls (R9). (a) 15-minute slots 07:00-23:45 IST plus 01:00, 03:00, 05:00 (recommended: matches "a few overnight polls", about 76 slots a day); (b) hourly from 00:00 to 06:00; (c) all 96 slots, every day.
